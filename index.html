Predictive analytics · Group project01 / 07

NYC Airbnb
Price Prediction

How much should a New York City Airbnb listing cost per night? This analysis compares a mean-price baseline, Linear Regression, and Random Forest using public listing characteristics.

  • Python
  • pandas / NumPy
  • scikit-learn
  • Matplotlib
  • Feature engineering
Read the report PDF (opens in a new tab)Explore the notebook ↗ (opens in a new tab)

Reported result

Random Forest achieved the strongest full-test-set RMSE and R². The tuned model achieved a slightly lower average absolute error.

Approach, results, and project files

Business question

Estimate nightly listing prices and explain how location, property characteristics, availability, reviews, and amenities relate to pricing.

Technical approach

  • Prepared public Inside Airbnb NYC listings and engineered geographic, amenity, availability, and review features.
  • Split training and test data; used imputation and one-hot encoding, with scaling for Linear Regression.
  • Modeled log-transformed prices and evaluated predictions in dollars using RMSE, MAE, and R².
  • Compared the baseline and two model families, then tuned Random Forest with randomized search.

The results support rough pricing guidance for typical listings. High-priced outliers increase error, and the analysis does not establish an increase in bookings or revenue.

AI evaluation05 / 07

Grounding an AI
Knowledge Assistant

A controlled HR-policy test exploring how source knowledge, role instructions, and explicit process rules affect the reliability of an AI assistant’s answers.

  • Prompt design
  • Knowledge grounding
  • Source approval rules
  • Test logging
  • AI evaluation

“Information not found.”

Required fallback when approved documents do not support an answer.
Download the evaluation DOCX

Observed finding

Explicit process rules changed how the assistant handled missing information and rejected policy drafts in the logged tests.

Test design, findings, and recommendations

Evaluation design

The log includes an ungrounded baseline, a knowledge-only project, a knowledge-and-role project, and a fully grounded project. The same childcare-stipend question was used across the three project configurations.

Process controls

  • Use approved policy documents and ignore drafts, rejected documents, and superseded sources.
  • Cite the policy title and section when an approved document supports the answer.
  • Use a fixed missing-information response instead of inferring that a benefit does not exist.

What the tests showed

The fully grounded project used the fallback for unsupported questions and cited approved policies for supported questions. Role instructions alone did not materially change source selection in this comparison.

Scope

Four configurations and seven logged tests provide a small evaluation, rather than a broad reliability benchmark. Recommendations include document approval controls, version management, and repeatable testing.

Observed responses and assessment are preserved in the supplied test report.
